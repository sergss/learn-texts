# PRD (Документ требований к продукту): Тренажер по английскому языку (Sivka-Burka)

## 1. Введение
В данном документе описывается текущая реализация приложения «Тренажер по английскому языку». Приложение представляет собой веб-инструмент для интерактивного изучения и запоминания английских текстов через различные упражнения. Текущая версия настроена на работу со сказкой «Сивка-Бурка» (Sivka-Burka).

## 2. Обзор продукта
Приложение является одностраничным (SPA) веб-интерфейсом, который ведет пользователя по тексту предложения за предложением. Оно обеспечивает визуальную и звуковую обратную связь для закрепления материала.

### 2.1 Целевая аудитория
*   **Основная:** Русскоговорящие ученики, изучающие английский язык.
*   **Вторичная:** Учителя или родители, помогающие ученикам.

## 3. Функциональные требования

### 3.1 Управление контентом
*   **Динамический контент:** Изначально загружается сказка «Сивка-Бурка». Пользователь может модифицировать список предложений (удалять).
*   **Хранение данных:** Состояние текста сохраняется в `localStorage` браузера, обеспечивая персистентность между сессиями.
*   **Навигация:** 
    *   Последовательная: кнопки «Следующее» и «Назад».
    *   Произвольная: клик по предложению в режиме просмотра полного текста.
*   **Сброс:** Возможность вернуть текст к исходному состоянию (Factory Reset).

### 3.2 Режимы обучения
Приложение поддерживает три режима взаимодействия, которые можно переключать в любой момент:

1.  **Просто читать (Read Mode):**
    *   Отображает полный текст предложения.
    *   Предназначен для первичного ознакомления и практики чтения.

2.  **Собрать слова (Assemble Mode):**
    *   Целевое предложение скрыто.
    *   Слова из предложения представлены в виде кнопок в случайном порядке.
    *   **Взаимодействие:** Пользователь кликает по словам в правильном порядке для восстановления предложения.
    *   **Валидация:** Проверка в реальном времени. При успехе появляется позитивная обратная связь и включается озвучка. При ошибке выводится сообщение о необходимости повторить попытку.
    *   **Управление:** Кнопка «Сброс» для очистки текущей попытки.

3.  **Вставить пропуски (Gaps Mode):**
    *   Отображает предложение, где некоторые слова заменены полями ввода.
    *   **Логика:** Слова длиннее 3 символов скрываются с вероятностью 40%.
    *   **Взаимодействие:** Пользователь вводит пропущенные слова в поля.
    *   **Валидация:** Кнопка «Проверить» сверяет ответы. Правильные ответы подсвечиваются зеленым, неправильные — красным. Пунктуация при проверке игнорируется для гибкости.

### 3.3 Аудио-функции
*   **Синтез речи (TTS):** Используется браузерный API `SpeechSynthesis`.
*   **Настройки голоса:** Настроено на 'en-GB' (Британский английский) с уменьшенной скоростью (0.8) для лучшего восприятия.
*   **Триггеры:**
    *   Ручной: кнопка «Прослушать».
    *   Автоматический: при успешном завершении задания в режимах «Сборка» или «Пропуски».

### 3.4 Пользовательский интерфейс (UI)
*   **Стиль:** Игровой, «комиксный» стиль с использованием шрифта 'Comic Sans MS', закругленных углов и ярких цветов.
*   **Управление текстом:**
    *   **Полный текст:** Скрываемая панель со всем текстом сказки. Текущее предложение подсвечивается. Поддерживается клик для перехода.
    *   **Администрирование:** Кнопки для удаления текущего предложения и полного сброса текста.
*   **Система обратной связи:**
    *   Визуальные индикаторы (зеленый текст для успеха, красный — для ошибок).
    *   Счетчик прогресса (например, «Предложение 1 из 16»).
*   **Адаптивность:** Базовая центрированная верстка, подходящая для десктопов и планшетов.

## 4. Техническая архитектура

### 4.1 Технологический стек
*   **Frontend:** HTML5, CSS3, чистый JavaScript (Vanilla JS).
*   **Развертывание:** Локальное (на базе файлов).
*   **Внешние зависимости:** Отсутствуют (используются нативные Browser API).

### 4.2 Структура данных
*   **Runtime:** Текст хранится в переменной `story` (массив строк).
*   **Persistence:** Используется `localStorage` (ключ `sivka_story_data_v1`) для сохранения изменений пользователя.

## 5. Планы по развитию (вне текущего объема)
*   Поддержка нескольких текстов/историй.
*   Система аккаунтов для сохранения прогресса.
*   Оптимизация под мобильные устройства.
*   Backend API для динамической загрузки контента.
